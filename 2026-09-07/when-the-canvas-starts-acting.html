当画布开始自主行动，谁真正掌握控制权？

来源：UX Collective 作者：Aurélie Radom 发布日期：2026-09-02 原文：链接

Agentic 交互界面正在改变设计师掌控的对象——从交互设计到代理能力、编排与注意力。

在软件发展的大部分历史中，界面是人们告诉系统该做什么的地方。我们点击、拖拽、输入和选择，系统做出响应。大量交互设计的工作就是让这些操作更容易理解，让下一步变得显而易见。

终端一直是一种不同类型的界面。它赋予你很强的能力，但大部分能力隐藏在命令背后。你需要知道系统能做什么以及如何要求它去做。这是设计师一直难以适应终端工具的原因之一——它们暴露的是机器的语言，而非工具的可能性。

AI 编程 agent 正在将这种交互模型带回来。你可以描述一个结果，然后让 agent 决定运行哪些命令、修改哪些文件、执行哪些测试。你不再需要逐步操作软件，但一个熟悉的设计问题以另一种形式重新出现了：系统理解了什么？它正在做什么？它改变了什么？我能阻止什么？我应该审查什么？

界面不再仅仅是我们操作的对象——它可以自主行动。

什么都不透露的界面

第一代生成式 AI 让这个问题变得尤为明显。我们面对一个空白输入框，被要求描述我们想要什么。这看起来像是另一个版本的"白纸问题"：当没有任何东西可以回应时，很难知道从哪里开始。

Takuma Kakehi 的文章《Nobody wants a blank page. Nobody touches a perfect one》探讨了创意工具中的这种张力，主张在"没有任何可操作素材"和"被 handed 一个已经感觉完成的东西"之间应该有一个中间地带。但 AI 界面引入了一个不同的问题。

空白提示词的困难不仅仅在于它要求我们从零开始。它的困难在于它不给我们任何关于可能性的提示。系统的能力隐藏在语言背后，意味着用户必须已经知道该问什么，才能发现工具能做什么。

因此，界面将探索的负担置于用户身上。它不是揭示自身的可能性并邀请实验，而是要求用户先去想象这些可能性。

正是在这里，我们多年来在交互设计中使用的一些原则重新变得相关。优秀的界面一直都在帮助人们理解什么是可能的，而不要求他们已经理解系统。它们提供 affordance（可供性），展示正在发生的事情，并给人们足够的上下文来决定下一步该做什么。空白提示词将大部分责任重新推给了人。

启发式原则依然重要

Nielsen 启发式原则为我们思考这种新关系提供了有用的框架。系统状态可见性意味着人们需要理解 agent 理解了什么、正在做什么以及处于流程的哪个阶段。识别而非回忆变成了一个问题：如何通过面前已有的上下文和素材来让 agent 的能力可见，而不是期望人们记住正确的命令或构建完美的提示词。用户控制与自由现在包括中断、重定向或撤销操作的能力。错误预防意味着定义 agent 应该被允许独立做什么，什么应该需要人的参与。原则依然存在，但它们描述的关系已经改变了。

我们过去设计的是等待指令的软件。现在我们设计的是能够理解意图、采取行动并决定何时需要我们的软件。

当画布开始行动

这就是画布变得自主的地方。Miro 的 agentic 画布将来自 Slack、GitHub、Amplitude 和 Granola 等工具的上下文，以及 PDF、演示文稿、电子表格和截图，汇聚到一个共享空间中。不再是页面、幻灯片或聊天记录，画布变成了一个空间环境，你可以缩放、平移、分组想法并连接不同的工作片段。它的 Sidekicks 能够理解这些上下文并创建文档、图表、原型或看板，而 Flows 将这些交互转化为团队可以查看、运行和复用的工作流。

重要的转变在于，AI 不再从孤立的提示词工作。它可以读取画布、引用上游资源，并将输出从一个步骤传递到下一步。价值不仅在于 AI 创建了什么，还在于这些工作成果落地在哪里。人们可以检查输入、更改输出并在其基础上继续构建。

Figma 正在朝类似的方向发展。其 设计 agent 直接在画布上工作，而 Figma Make 使用户能够从创意和现有设计走向可工作的原型和应用程序。公司还向第三方 agent 开放了画布，并引入了 skills，为 agent 提供关于设计决策和意图的上下文，这与 Anthropic 生态系统中 skills 的运作方式相呼应。

Miro 看板包含项目的上下文。Figma 文件包含组件、布局和关系。代码库包含文件、依赖项、测试和错误。Agent 有了可以操作的东西，这改变了交互的本质。但还有另一个转变：agent 不仅仅在消费上下文，它们开始决定需要哪些上下文。

Google DeepMind 在 agentic video 理解方面的工作是一个很好的例子。Gemini 不再将视频作为固定帧流来处理，而是可以确定需要检查视频的哪个部分、以什么速度，以及是否需要帧、音频还是转录文本。它可以通过 agentic loop 检索与任务相关的时刻和信号。这听起来可能像是一个技术优化，但它指向了界面中更大的变化。系统不再只是等待我们为它指向正确的信息。它可以自行确定哪些信息与任务相关并自行检索。

同样的模式正在 agentic 画布中出现。画布为 agent 提供了工作的环境，但 agent 也在导航这个环境。它可以找到相关上下文、跨工具连接信息、决定要操作什么并将结果传递下去。上下文不再只是系统接收的东西，而是系统可以主动寻求的东西。

这意味着注意力成为了设计问题的一部分。

Human in the loop

我们花了很多时间讨论如何让人类保持在回路中。Ge Wang 在他的斯坦福文章 Humans in the Loop: The Design of Interactive AI Systems 中做了一个有用的区分：自动化一个任务与设计一个让人们仍然能够影响结果的系统是不同的。

人类参与不一定意味着手动完成工作。它可以意味着决定 agent 应该在哪里自主行动、在哪里应该汇报、在哪里需要人来做决定。目标不是在"全部自己做"和"全部交给 AI"之间做非此即彼的选择，而是一种更灵活的责任分工。

这对 agent 来说尤其相关。想象你要求一个 agent 规划旅行。我可能给它我的预算、偏好和大致想去的地方，然后让它搜索选项并制定行程。我不希望批准每一个搜索或预订步骤，因为那等于我在做大部分工作。但我也不希望 agent 替我做每一个决定。如果两家酒店差不多但其中一家位于我不喜欢的街区，或者最便宜的航班涉及不方便的过夜中转，这些是需要上下文和个人偏好的决策。Agent 可以处理常规工作，然后把这些决策带回来给我。工作在我们之间流动，取决于谁更适合处理。

AI in the loop, humans in charge（AI 在回路中，人类掌控全局）概括了这里最重要的东西。人类参与不应以一个人必须点击多少次"批准"来衡量。真正重要的是人们是否在依赖判断力、上下文或偏好的决策中保持控制权。设计这个边界——决定 agent 应该处理什么、应该呈现什么、何时应该将控制权交还——是一个编排问题。

设计交接

一旦系统能够行动，交接就成了界面的一部分。我们需要决定 agent 何时应该在没有我们的情况下继续、何时应该询问、何时应该将工作返回等待决策。这意味着我们要设计的不只是屏幕和交互。

我们在设计人与系统之间的责任分配。

一旦我们开始为能自主行动的系统做设计，过去游离于界面之外的决策成为了设计的一部分：

  • Agent 可以在不询问的情况下做什么？
  • 何时应该请求确认？
  • 哪些操作应该是可逆的？
  • 哪些决策应该始终由人来做出？

这些选择在传统意义上可能看起来不像界面设计，但它们对体验的塑造与屏幕或交互一样深刻。这就是 agency 成为设计材料的地方。

那么设计师在设计什么？

如果人类不再直接操作界面，很容易认为界面设计师的角色变得不那么重要了。我认为恰恰相反正在发生，但设计的对象正在转移。

我们仍然设计屏幕、组件和交互，但我们也在设计行为、约束、默认值、权限和结果。我们还在决定系统可以不经询问做什么、需要许可做什么，以及哪些情况应该将人重新带入流程。这些大部分永远不会作为传统界面元素出现。它存在于决定系统如何行为的规则和假设中。

这是产品的策略层。

设计师不再仅仅定义人们操作系统的界面。他们在定义系统自行运作的条件。这已经开始改变我们对设计系统和设计知识的思考方式。Figma 围绕 agent 和 skills 的工作指向了一个未来：曾经主要存在于设计师脑中或设计文档中的决策和约定，可以成为 agent 工作的上下文的一部分。

设计系统可以成为塑造机器如何运作的指令和约束的一部分，而不仅仅是人类设计师的参考。

这也改变了"品味"（taste）的含义。

当 AI 能够生成各种可能性时，品味帮助我们决定哪些值得追求。当 AI 能够执行决策时，品味还帮助我们决定哪些决策应该属于人类、哪些可以委托。设计师塑造的不仅是结果，更是产生结果的 agency 分配方式。

什么值得我们的注意力？

这种转变还有另一个后果。如果 agent 能够收集上下文、生成选项、做出修改并推进工作，执行就变得不那么稀缺了。注意力变得更加重要。但现在有两种注意力需要考虑：系统关注什么，以及它要求人类关注什么。

设计师不需要做每一个决定，他们需要识别哪些决定值得做。这改变了 human in the loop 设计的含义。目标不是让一个人参与每一步。而是确保正确的东西到达他们面前。

一个 agent 可能检查数百个文件、比较数十个选项或搜索数小时的视频而不涉及我们。设计问题是决定当它确实需要我们时应该呈现什么，以及什么应该被信任由它自行处理。人类注意力成为系统可以帮助分配的资源，而这正是智能界面、编排和品味交汇之处。

设计师的角色正在从"指定每一个交互"转向"决定责任和注意力应如何 在人与系统之间流动"。

我们在设计系统能看到什么、能做什么、应该留什么不动，以及何时应该向我们请求。当画布开始行动时，我们仍然在设计界面。但现在我们还在设计其背后的行为、围绕它的边界，以及控制权回归人的那些时刻。

也许问题不再仅仅是界面应该长什么样。而是：谁应该决定下一步发生什么，以及当它发生时，谁应该给予关注。
