对话设计：如何让你的 AI Agent 像团队一样沟通

如果你的团队没有人培训过 Agent 应该如何沟通，那么当它与客户对话时，它会听起来像 LLM（因为它就是）。

对话设计是 AI 优先支持团队中出现的新兴学科，专门用来解决这个问题。对话设计师负责定义 Agent 的沟通方式：语气、结构、详细程度、客户体验、转接和升级流程。

如果没有专人定义 Agent 应该遵循的沟通指导，它就会自己做出决定。这可能导致：在简短回答就足够的情况下给出过多细节；在客户感到沮丧时用平淡的语气回复；或者触发转接的时间太晚。

所有这些成本都是可衡量的。收到结构尴尬回复的客户不太可能信任答案，即使答案准确，他们也会升级到人类队友那里，听到同样的事情用不同的方式表达。其他人会完全跳过 Agent。当 Agent 确实转接时，糟糕的过渡意味着人类支持代表要面对已经感到沮丧的客户。每一个这样的结果都是可以避免的，而对话设计正是确保它们不会发生的学科。

我们在 Fin 亲身经历了这一点。我们对两种开场消息进行了 A/B 测试，一种是温暖和对话式的，另一种是我们之前的默认版本。对话式的问候将 CSAT 从 72.8% 提升到 78.4%。一个单一的对话设计变更，应用到客户看到的第一件事上，就产生了可衡量的差异。

对话设计涵盖什么

这个角色涵盖五个不同的领域，每个领域都塑造着客户体验的不同部分：

领域 描述
语气和个性 声音、详细程度、Agent 听起来有多正式或多随意，以及这些是否会根据情况变化。
回复结构 Agent 是否将详细程度与客户的请求相匹配。
转接逻辑 何时升级、如何沟通过渡、以及要传递什么上下文。
交互流程 对话如何通过提问、回答、解决或转接来推进。
回复质量 答案是否感觉清晰、有帮助、符合品牌调性，即使在技术上正确时。

如何付诸实践

从对话应该给人的感觉开始

在调整单个回复之前，先定义声音。用一段话写下来你希望 Agent 听起来怎么样。你不需要完整的品牌指南，只需要一个在做关于语气的决定时可以回溯的参考点。

不同的对话类型可能需要不同的语域。被锁定在账户外的客户需要直接和速度，而探索新功能的人可能欣赏更多上下文。声音保持一致，但语域应该适应。

仔细设计转接

从 Agent 到支持代表的过渡是摩擦最大的时刻之一。客户不应该重新解释他们的问题。代表应该收到完整的对话历史、问题背后的上下文、Agent 已经做了什么、以及为什么升级。

Agent 沟通转接的方式也很重要。"让我为你连接一位可以帮助解决这个问题的队友"与无声转接的感觉是不同的。

设计故障安全机制也很重要。如果 Agent 无法干净利落地解决对话，你需要一个仍然能给客户流畅转接体验的后备方法。客户在那时可能对 AI 感到沮丧，但处理得当的过渡可以扭转局面。

别忘了跟进

跟进需要与转接同样的关注。如果有人在对话中途掉线，无论是与你的 Agent 还是支持代表，你如何重新联系以确保他们得到了所需的帮助？大多数团队不考虑这一点，而客户会注意到。

知道 Agent 何时应该停止说话

最常见的对话设计错误之一是过度解释。Agent 可以访问大量信息，如果不加引导，它很容易给出比客户需要更多的细节。

Agent 应该将详细程度与客户的请求相匹配。询问如何重置密码的人不需要三段话。询问复杂集成的客户可能需要。如果有更多要分享的内容，它应该主动提供，而不是一次性全部给出。

为客户正在进行的对话而设计

客户不遵循脚本。他们会在对话中途改变方向，或提出与原始问题无关的后续问题。

Agent 需要处理这些过渡，而不强迫客户回到固定流程。当客户已经转移话题后，Agent 仍然试图解决原始问题时，会让人感觉像是在与一个没有在听的人交谈。

考虑同样的流程是否应该适用于不同的渠道，以及不同的客户群体是否需要不同的体验。

保持指令简短

最大的实际挑战之一是对 Agent 的过度指导。每次出现新的边缘情况时，团队都会添加规则。不久之后，LLM 在响应之前需要处理大段指令。

我在 Fin 见过这种情况，也从其他团队听到过同样的情况。本能总是添加更多，但纪律在于知道何时停止。

我的规则：如果是关于内容或信息，它属于知识库。如果是关于语气或如何处理特定情况，它属于 Agent 的指令。"对定价直接"比解释定价沟通策略背后理念的一段话更有效。

如果你正在使用 Fin，大部分工作在 Guidance 中进行。这是对话设计成形的地方，帮助你定义 Agent 应该如何听起来、应该说多少、以及在不同情况下应该如何回应。

没有专人也能开始

大多数团队不会在第一天就雇佣专门的对话设计师——这没问题。但需要有人负责 Agent 如何沟通，即使这是现有角色的一部分。

对话设计通常从支持运营或知识管理开始。团队中的某人开始关注 Agent 的声音。随着时间的推移，当你的 Agent 处理更多对话时，这变成了正式责任，最终成为专门角色。

从哪里开始

1. 指定负责人

你需要有人对 Agent 如何沟通负责。不需要是新员工，但需要明确指定。

2. 选择一个表现不佳的对话类型

查看 Agent 回答正确但客户仍然升级或留下负面反馈的对话。从那里开始。

如果你正在使用 Fin，CX Score 可以帮助你找到这些。它显示哪些主题和对话类型得分低，以及这些得分背后的原因，这样你可以看到问题是答案质量、客户努力还是其他原因。

3. 审计你的 Agent 指令

如果它们已经超出了几条聚焦规则的范围，精简它们。将内容移到知识库，保持指令聚焦于行为。

4. 修复你最糟糕的转接

查看一些 Agent 升级到人类的对话。客户必须重复自己吗？支持代表有足够的上下文吗？先重新设计那单一过渡。

小步积累，成效显著

这些改进中每一个的影响都会累积。温暖的开场消息提高了我们的 CSAT，而精简指令使响应更敏锐。设计更好的转接意味着支持代表不再接手已经沮丧的客户。

这些变化都不需要新知识；它们需要有人关注对话本身。
