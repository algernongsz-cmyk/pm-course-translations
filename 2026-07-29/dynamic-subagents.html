Deep Agents 中的动态 Subagent

作者：Sydney Runkle, Colin Francis, Hunter Lovell | 日期：2026年6月29日 | 原文链接

随着 Agent 承担越来越有挑战性的任务，它们面临着困境：

我们一直在试验一种称为"动态 subagent"的方法来应对这些挑战：Agent 不再通过通用的工具调用来发布 subagent 任务，而是编写一个简短的脚本来驱动 subagent 的执行。这意味着模型可以依赖它擅长的代码模式（如循环、分支或并发）来编写适合任务的编排逻辑。

为什么需要动态 subagent？

Deep Agents 已经支持 subagent。它们隔离上下文，让主 agent 委托离散的工作单元，并将中间结果排除在主上下文窗口之外。那么，为什么我们需要动态 subagent？

对于普通的 subagent，它们是由主模型直接调用的，一次调用一个。这在规模较小时是有效的。但当你需要生成数百个 subagent，或者编排逻辑是条件性或多阶段时，这种方法就会崩溃。

动态 subagent 通过程序化编排解决了这个问题。Agent 不再逐轮进行工具调用，而是编写一个简短的脚本来编排和调用 subagent，并在一个轻量级解释器中运行它。

典型例子：一个 300 页文档的每一页对应一个 subagent。Agent 不需要调用 subagent 工具 300 次，而是编写一个循环：

const results = await Promise.all(pages.map(page =>
  task({ description: `Summarize page ${page.number}`, subagentType: "summarizer" })
));

这解锁了基于工具调用的编排无法可靠实现的两件事：

  1. 大规模的确定性覆盖。没有结构，agent 会就范围做出判断，审查 500 个项目中的 75 个就宣布完成。分派循环不会这样。覆盖成为一个结构性保证，而不是一个提示工程问题。
  2. 可靠的复杂编排。将编排写成代码比让模型将其重现为一系列工具调用更可靠，特别是对于扇出+合成、多阶段流水线或条件分支。

这与 Claude Code 和递归语言模型（RLM）中的工作流理念相同：模型编写代码，该代码分派更多的 agent。

快速开始

动态 subagent 需要两样东西：用于分派工作的 subagent，以及代码解释器：一个安全、轻量的运行时，模型在其中编写和执行编排代码。Deep Agents 包含一个基于 QuickJS 的可选代码解释器。要使用它，请安装 QuickJS 中间件包，然后通过 create_deep_agent 的 middleware 参数传递 CodeInterpreterMiddleware。

pip install -U "deepagents[quickjs]"
from deepagents import create_deep_agent
from langchain_quickjs import CodeInterpreterMiddleware

agent = create_deep_agent(
    model="openai:gpt-5.5",
    middleware=[CodeInterpreterMiddleware()],
)

Deep Agents 内置了一个通用 subagent，因此已经有一个可在工作流中使用的通用 subagent 配置文件。对于专门的工作流，配置具有自己名称、描述和系统提示的自定义 subagent：名称和描述是 agent 知道调用哪个角色的方式。

要触发动态 subagent，请在提示词中使用"workflow"一词，如下所示：

result = await agent.ainvoke({
    "messages": [{"role": "user", "content": "Run a workflow that reviews every file in src/routes/ and summarizes the top risks."}]
})

与编码 Agent 一起使用

尝试动态 subagent 的最快方法是使用 dcode，这是我们的终端编码 agent，基于 Deep Agent 构建。它默认启用了代码解释器，因此无需任何配置——动态 subagent 开箱即用。

安装

curl -LsSf https://langch.in/dcode | bash

运行

dcode

要触发动态 subagent，只需请求"workflow"。Agent 不会自己艰难地完成工作，也不会尝试用其原生任务工具管理 subagent 扇出，而是编写一个调用内置 task() 全局函数的编排脚本，并在代码解释器中执行它。例如："运行一个工作流，审查 src/ 中的每个文件是否存在 SQL 注入。"

当 subagent 生成时，dcode 会在动态 subagent 面板中实时显示它们，按分派阶段分组。

你可以用 dcode 最快地尝试这个，但也可以通过 ACP 在你选择的工具中使用（例如 Zed）。

工作原理

Agent 获得一个 eval 工具。它编写 JavaScript，在解释器中安全执行。当配置了 subagent 时，解释器暴露一个内置的 task() 全局函数，从代码中分派它们。根据手头的任务，模型编写不同的代码——循环、分支、Promise.all——解释器确定性地运行它。

task() 接受描述、subagentType 和可选的 responseSchema——当提供时，结果已经是一个类型化对象，准备好过滤或传递给下一步。

const result = await task({
  description: "Review src/auth/login.ts for security issues.",
  subagentType: "reviewer",
  responseSchema: {
    type: "object",
    properties: {
      severity: { type: "string", enum: ["high", "medium", "low"] },
      issues: { type: "array", items: { type: "string" } },
    },
  },
});

const critical = result.severity === "high" ? result.issues : [];
critical; // model sees the last line

更多信息，请参阅文档中的程序化 subagent和解释器。

常见编排模式

Anthropic 的动态工作流推广了一组并行 agent 工作的编排模式。它们不是你开启的功能。它们是从工作中自然形成的形状，agent 会随着任务的变化而陷入不同的模式。下表将每种形状映射到适合的工作类型。

下面我们将深入了解每种模式在 Deep Agents 中的工作方式，并提供实时追踪。我们还制作了一个解释这六种模式的视频，你可以在这里查看。

分类后行动（Classify and act）

项目首先被分类，然后根据其分类由专门的 subagent 处理每个项目。这让你可以处理混合输入，其中不同项目需要不同的专业知识。

使用场景：分类支持工单、错误日志、用户反馈，或任何需要根据类型进行不同处理的批量项目。

示例：分类支持工单积压。Agent 读取工单并将每个工单分类为错误、功能请求或问题。错误发送给 bug-investigator，功能请求发送给 feature-analyst，问题发送给 support-responder。结果是按类别分组的摘要。

查看追踪。

扇出并合成（Fanout and synthesize）

Agent 并行地将相同类型的工作分派到多个项目，然后合并结果。

使用场景：跨目录的代码审查、分析一批文档、处理日志文件、跨多个服务运行相同的检查。

示例：跨源代码树的逐文件安全审查。Agent 发现 src/ 下的每个 TypeScript 文件，并并行地为每个文件分派一个 security-reviewer。然后，它将结果合并为一个按严重性评级排序的单个报告，并指出需要更改的行。

查看追踪。

对抗性验证（Adversarial verification）

两轮模式。第一轮产生发现。第二轮将每个发现发送给独立的验证者，只有通过一致的发现才会被保留。当置信度比速度更重要时，这可以减少误报。

使用场景：误报成本高的安全审计、合规检查、任何需要对发现具有高置信度的审查。

示例：不允许误报的安全审计。审计员广泛搜罗潜在漏洞，然后每个发现交给一个独立的验证者，该验证者重新阅读代码并返回 CONFIRMED 或 REFUTED 裁决。只有确认的发现进入最终报告。

查看追踪。

生成并过滤（Generate and filter）

多个 subagent 为同一问题生成独立的解决方案。Agent 在代码中比较、评分和过滤结果，只保留最好的。

使用场景：架构提案、重构策略、内容变体、任何在提交前探索多个选项以产生更好结果的任务。

示例：竞争性的限流器重设计，排名。Agent 使用架构师生成 rate-limiter.ts 的几个独立重设计，每个写入自己的文件，以免相互覆盖。然后，它在突发下的正确性、多实例支持和复杂性方面对它们进行评分。最强的一个获胜，并附带理由。

查看追踪。

锦标赛（Tournament）

变体由裁判 subagent 进行一对一比较，获胜者通过淘汰赛晋级。

使用场景：主观标准下的优化、风格选择、在竞争实现之间做出选择。

示例：对混乱的 createOrder 处理程序重写进行成对淘汰赛。几个编写者各自产生不同优先级的候选重写，然后裁判将它们一对一比较，逐轮晋级获胜者，直到一个冠军脱颖而出。它返回裁判的推理。

查看追踪。

循环直到完成（Loop until done）

Agent 运行发现循环，对已经发现的内容进行去重，直到没有新结果出现。当工作范围事先未知时很有用。

使用场景：穷举搜索、死代码检测、依赖审计、任何追求完整性而非固定数量结果的扫描。

示例：基于遍历的安全扫描。Agent 运行扫描遍历，检查在代码中发现的内容，只有当前一次遍历发现新问题时才启动另一次遍历。当一次遍历没有发现新内容时停止。它报告合并的发现和遍历次数。

结论

动态 subagent 是如何赋予 agent 更多自主权和更高可靠性的方式。代码处理覆盖和中间上下文，模型仍然执行判断密集型工作。上述模式是一个起点。在实践中，agent 会根据任务需求组合和混合它们。

这是递归语言模型理念的最简单形式。一个编写代码的 agent，该代码分派更多的 agent。这是一个递归调用自身的 agent，不受上下文窗口限制，也不被固定在固定工作流中。Agent 可以将问题分解到底，并以任何适合的形状重新组装碎片。上面强调的编排模式是可能性的早期瞥见，但随着模型在编写代码方面越来越好，上限只会继续提高。

动态 subagent 是 Deep Agents 今天将其交到你手中的方式。通过向你的 agent 添加代码解释器开始，或者使用 dcode，那里动态 subagent 开箱即用。
