AI 在客户服务领域已不再是实验性的，而是标准配置。

Fin 的《2026 客户服务转型报告》发现，82% 的高层领导者表示他们的团队在过去 12 个月中投资了客户服务 AI，87% 计划在 2026 年继续投资。

AI 优先的客户服务带来的好处令人惊叹：7x24 小时可用、多语言支持、大幅节省时间，以及为客户提供快速高效的解决方案。但在每一次出色的 AI 驱动支持体验背后，都有一位无名英雄：知识管理。

Service Agent 的能力取决于你给它提供的内容。如果你使用像 Fin 这样的 Agent 来端到端地解决客户查询，它需要一个广泛的知识池来提取。你需要为它提供关于产品、功能、政策和故障排除的准确答案。没有这些，你的 Agent 就无法完成工作，你的支持团队又要回到手动解决本可以自动处理的查询。

本指南涵盖知识管理旅程的两个不同阶段：

  • 阶段 1：构建知识库——适用于从零开始或对现有内容进行重大改造的团队。
  • 阶段 2：知识管理——适用于已有内容并专注于维护、优化和扩展的团队。

如果你已经拥有扎实的知识库并想直接进入优化和维护，请跳至阶段 2。

什么是知识管理，为什么如此重要？

定义：知识管理是在企业中创建、组织、共享和维护知识的过程。

面向客户的知识库是一个典型例子，但你的帮助中心文章只是知识管理冰山的一角。实际上，知识管理涉及一系列活动，例如：

  • 创建资源，如帮助中心 FAQ、故障排除指南、入职和最佳实践文档、博客、内部支持指导和学习材料。这些共同涵盖了客户可能遇到的所有问题、任务和场景，从简单的操作指南到更复杂的产品、计费和账户问题。
  • 识别缺口，如缺失的故障排除步骤、不清晰的政策解释、过时的功能详情或未回答的边缘情况。
  • 实施系统，使你的 Agent 和支持代表在解决客户问题时能够轻松访问和使用这些信息。
  • 开发流程，确保现有材料持续更新以反映政策变化、产品更新或错误修复。

为什么在 AI 时代知识管理比以往任何时候都更重要？

你的知识库不再仅服务于那些想自行解决问题的客户。它现在驱动着你的整个支持体验。

这是准确回答复杂客户查询、加快解决和处理时间以及让客户满意的关键。

以下是知识管理成为每个前瞻性支持领导者关注重点的两个原因：

1. 你的 Agent 的能力取决于你"喂"给它的内容

你的 Agent 的好坏取决于它所训练的知识。缺乏信息、结构不良的文章或过时的文档都会阻止它为客户提供清晰正确的答案，导致糟糕的客户体验，损害信任并达不到他们的高期望。

没有大语言模型（LLM）像你一样了解你的业务。它不了解客户的需求、痛点和使用场景。这些知识对你和你的组织来说是独特的，这意味着你需要成为那个将其全部映射出来并让 Agent 可用的人。

2. 对知识的每一项投资都有复利效果

转向 AI 不仅仅是采用新工具。它意味着适应新的生态系统。你越早开始播种，就能越早收获回报。

它就像飞轮一样工作。你对知识库的每一次改进都会让你的 Agent 更有效。它带来更多的解决方案和更好的数据，这告诉你接下来应该添加、更新或优化什么。你投入越多，这些收益就会复利增长。

无论你是雇佣专人全职做这项工作，还是让支持代表每周有时间离开收件箱，ROI 都不言自明。

这样想：假设写一篇针对常见问题的故障排除新文章需要 30 分钟。这 30 分钟的投资会带来：

  • 为支持代表节省数小时，他们不再需要花时间回答那个查询，因为现在你的 Agent 可以处理了。
    • 计算：平均回复时间 × 查询频率 = 为团队节省的时间。
  • 数百名满意的客户，他们获得即时、准确的答案，无需等待可用的代表。
    • 计算：提出此查询的客户数量 × 平均解决时间 = 为客户节省的总时间。
  • 关于帮助文档和 AI 支持体验的数据，供你学习，以便让它们更有效。
    • 监控：Agent 参与率、解决率和自动化率。

对于半小时的工作来说，这是一个相当不错的 ROI。开始生成这些数据的最佳方式就是直接开始。你越早开始，就能越早捕捉到关于内容缺口、客户在哪些方面遇到摩擦以及如何改进支持体验的洞察。

阶段 1：构建知识库

本阶段涵盖让知识库准备好为 Agent 提供动力所需的一切：包含什么内容、如何获取、以及在上线前如何审核和优先处理。

知识库应包含的内容

整理和优先处理所有内部和外部支持文档可能感觉像是一项艰巨的任务，但有了正确的技术帮助你，它不必如此。使用完整的 AI 驱动平台的好处是它为你提供：

  • 数据驱动的洞察，帮助你根据客户实际在寻找什么来识别和优先创建帮助内容。例如，在 Fin 中，Recommendations 从真实的客户对话中浮现知识缺口，在那些地方帮助内容缺失、不清晰、重复或相互矛盾。
  • 一个集中创建、管理和优化知识内容的地方。例如，Intercom 的 Knowledge Hub 使你能够为客户面向和内部支持内容创建单一事实来源。使用内容定位，你可以细分这些信息，确保 Fin 只使用你想要的确切内容来帮助客户和团队。

无论你是刚开始还是想要一个复习清单，以下是一些应优先为 Agent 包含在知识库中的信息示例：

1. 支持 FAQ

  • 内容：回答客户最常见的支持问题，从日常支持中出现的计费和账户变更到功能使用、故障排除和政策问题。
  • 信息来源：寻找你的团队在收件箱中回答最多的问题，然后使用这些模式来构建或扩展帮助中心内容。
  • 使用场景：帮助中心、Agent、Copilot 和主动支持（如产品内工具提示）。

2. 入门和设置指南

  • 内容：帮助客户快速上手、完成设置并开始从产品中获得价值的资源。
  • 信息来源：与你的客户成功团队或入职专家交谈，了解他们的入门建议，或要求你的产品团队在构建新功能时记录此过程。
  • 使用场景：帮助中心、Agent、Copilot、产品导览。

3. 故障排除和高级指南

  • 内容：帮助客户解决更复杂问题、处理边缘情况以及在基础知识就位后从产品中获得更多价值的资源。
  • 信息来源：获取产品经理、R&D 和客户成功经理等内部专家的输入，以记录更深入的故障排除步骤、已知限制和建议的变通方法。
  • 使用场景：帮助中心、Agent、Copilot，以及针对高级用户的目标消息（如应用内消息或邮件）。

4. 特定用例和客户细分

  • 内容：针对不同类型客户的内容，他们有独特的目标、设置或待完成任务，这样你的支持可以更相关并为每个对话提供上下文。
  • 信息来源：使用来自产品、成功和支持团队的针对性指导，加上真实的客户对话，展示不同客户如何描述他们的目标、工作流程和问题。
  • 使用场景：帮助中心、Agent、Copilot、定制网络研讨会、学习课程。

内容格式和来源

在为服务获取知识时，要广泛撒网。你可能已经在帮助中心、内部文档、网站和过去的对话中散布着有用的支持内容。关键是将其整合成你的团队、Agent 和 Copilot 可以实际使用的方式。

在 Fin 中，你可以使用：

  • 公开文章：帮助中心文章、故障排除指南、入职内容。
  • 内部文章：内部支持指导、升级步骤、政策澄清。
  • 过去的对话：可以帮助识别缺口并改进覆盖范围的以前支持交互。
  • 片段：针对常见回复、例外或批准措辞的短格式指导。
  • 网页：从公开 URL 同步的内容。
  • 文档：带有可选择文本的 PDF 和 DOCX 文件。

在 Intercom 的 Knowledge Hub 中，你可以在一个地方管理所有这些内容源，控制 Fin 和 Copilot 可以使用哪些源，并识别哪些内容表现最好，以便你可以持续改进。

审核现有内容

对现有内容进行审核

第一件事是审查你目前拥有的材料。这有两个原因：首先，你需要确保你的 Agent 不是从过时的信息中学习，其次，它识别了当前的缺口在哪里。

在 Fin，我们在将文章提供给 Agent 之前有超过 700 篇实时文章需要审核。为此，我们将文章按产品领域划分，并给相关团队一周时间来检查、更新或退役每篇文章。像这样分享所有权使其成为真正的团队努力，并将庞大工作分解为可实现的的任务。

如果你现在投资服务知识，你不仅仅是在改进今天的支持。你正在为以后更广泛的 Customer Agent 策略奠定基础。今天为服务提供动力的产品知识、故障排除内容、入职指导和客户上下文，也使以后更容易提供更主动、个性化的客户体验。

站在客户的角度思考

自己走过客户在寻求帮助时会采取的相同步骤，包括他们与 Agent 的首次接触。

这将帮助你测试答案的质量并发现内容中缺失的主题或关键词。

在上线前，自己测试以确保你体验到客户将拥有的相同支持旅程。如果你使用 Fin，可以使用 Preview 查看它如何实时响应并在发布前优化答案。批量测试帮助你检查更广泛的客户问题集的内容覆盖范围，并在发布前发现缺口。对于更复杂的工作流程，Simulations 帮助你验证它如何遵循每个步骤、处理交接，以及在到达客户之前内容和设置仍需改进的地方。

寻求团队的输入

在审核和识别内容缺口时，不要只依赖客户支持团队。采取"全员参与"的方法。通过包括产品和工程团队在此过程中，你可以从比你更了解产品的人那里获得专家建议。你的销售、营销和客户成功团队也将对什么对客户重要以及他们想实现什么有独特的见解。

使用 Agent 的初始数据

在使用 Agent 30 天后，你将有足够的数据看到它在哪些地方能够成功解决问题，而在哪些地方遇到困难以及原因。深入挖掘这些数据找到需要加强的领域。这些可能是没有足够内容让 Agent 处理并移交给支持代表的主题。它也可能突显由于解决率低或客户满意度分数低而需要改进的文章。

如果你在同一平台管理 Agent 和知识内容，你将能够获得关于内容在每个触点如何表现的详细报告，以便你可以准确指出需要集中精力的地方。

⚡ 专业提示：如果你刚刚开始，考虑先对一部分客户测试你的 Agent 以获得这些初始数据。然后，一旦你解决了任何立即的缺口，就可以进行更广泛的推广。

规划和优先处理

优先处理要更新或创建的内容

到现在为止，你可能已经从公司的各个角落涌现出惊人的支持内容想法。下一步：决定从哪里开始。

在优先处理内容时，你真正想做的是找出什么正在驱动你的客户支持团队的工作量，并识别最容易实现的成果来减少该工作量。为帮助你管理资源并处理影响最大的事情，请尝试这些提示：

  • 识别内容，你的支持团队最常分享或依赖的内容，如帮助文章、故障排除指南、入职内容和政策信息，并确保你的 Agent 首先能够访问这些内容。
  • 查看对话中的数据和指标，了解客户最常问的问题、他们在哪些地方遇到困难、哪些主题处理时间最长，以及客户体验（CX）分数在哪些地方最弱。然后围绕这些特定缺口创建或改进内容。
  • 基于主题对业务和支持运营的价值进行优先处理。例如，首先关注驱动最多支持量的议题、客户体验中摩擦最大的部分，或对高价值客户最重要的领域。
  • 使用报告找到浏览量最多的文章，并按"上次更新"筛选，找到一段时间未审查并可能需要刷新的帮助内容。如果你的产品、政策或计划发生了变化，立即更新该内容，这样你的 Agent 就不会基于过时的信息工作。

分配时间和资源

要有意识地安排时间处理支持内容。构建高性能的 Service Agent 不应该是副业。

在 Fin，一个由一线代表、支持专家和工程师组成的专门团队每周花时间离开收件箱处理知识和 AI 改进。通常，每个个人贡献者被分配 5-10 小时来执行内容请求、填补知识缺口，并将来自培训、测试和分析的见解反馈到知识库和 Agent 设置中。

这个团队一起执行内容请求、填补知识缺口，并将来自培训、测试和分析的见解反馈到你的知识库和 Agent 设置中。

⚡ 专业提示：这些项目是帮助你的支持代表提升技能并发展为 AI 在客户服务领域创造的令人兴奋的新角色的好方法。

AI 友好内容的最佳实践

如何编写内容与编写什么同样重要。这些最佳实践将帮助你创建你的 Agent 可以实际有效使用的内容。

使用客户使用的术语

在支持内容中使用正确的语言至关重要。语言是多样的，因行业、角色和职位而异。例如，支持代表可能称某人为客户，而另一个团队称他们为用户或管理员。分析你的搜索数据以发现客户使用的词语，并训练你的 Agent 说他们的语言。

⚡ 专业提示：在上线前，用不同群体测试你的 Agent，如新客户、高级用户或不同计划的客户。这揭示了人们如何以不同方式提出相同问题、发现内容中的缺口，并确保你的 Agent 为不同上下文提供正确答案。

简化语言并消除歧义

AI 友好的语言也意味着客户友好的语言。请记住，你不仅仅是为 Agent 编写，而是为具有不同技术水平水平的真实客户编写。尽可能保持语言清晰和无歧义。避免不必要的内部行话，拼写出任何缩略词，并清楚解释关键产品术语，这样你的指导就清晰明了。

在答案中添加上下文

如果你今天有一个人类可以解释的 FAQ 文档，并且其中有简单的是或否答案，机器不会像人类那样解释这些答案。你需要在说"是"时扩展你的意思，说"否"时扩展你的意思。为此，我们建议在答案中重述问题并在其后添加完整的上下文。这为你的 Agent 提供了更准确地回答客户问题所需的清晰度。

为图像和视频添加文本

展示和讲述都很好，但你的 Agent 不能仅依靠视频或图像作为事实来源，所以总是要在它们旁边包含清晰的解释性文本。这不仅使内容对 AI 更易访问，也使它对你的受众更易访问，确保有视觉或听觉障碍的客户不会被排除在外。

使用格式创建可扫描的结构

使用标题、列表和表格使内容易于扫描。清晰的 H1、H2 和 H3 帮助 Agent 和人类快速导航。避免隐藏信息或需要用户输入才能显示内容的动态交互元素（如下拉菜单）。

在 FAQ 文章中收集小信息

如果你有不需要完整文章的小块信息，将它们编译成内部片段列表或集中的 FAQ 列表。这可能包括常见的边缘情况、政策澄清或对高频支持问题的简短回答。因为这些通常是一些最重复的查询，将它们构建为小答案使你的 Agent 更容易快速找到并传递正确的回复。

阶段 2：知识管理

构建知识库后，重点转向随时间维护、优化和扩展它。这是知识管理成为持续职能而非一次性项目的地方。

上线并学习

跟踪指标以衡量成功

一旦开始使用 Agent，跟踪业务指标以衡量其产生的影响。一些相关的跟踪指标包括：

  • 解决率：Agent 有机会回答时完全解决的对话。
  • 自动化率：Agent 在整个支持量中处理的对话总数。
  • 节省的时间：从支持团队中卸载的手动工作小时数。
  • 客户体验（CX）分数：如果你在实时环境中测试 Fin，跟踪整体客户体验在 AI 和人工处理的对话中的比较情况。
  • CSAT：如果你在实时环境中测试，跟踪 AI 的客户满意度与人工处理交互的比较情况。

所有这些指标帮助你发现哪些内容表现最好，以及你可以在哪些地方改进知识管理流程。

将学习付诸行动

理想情况下，你会立即看到惊人的结果，但你不太可能立即得到所有正确的东西。你的 Agent 还会有一些无法解决的问题、需要优化的工作流程以及随时间揭示内容缺口的对话。

这很有用，因为它为你提供了关于客户需要什么以及支持体验可以在哪些地方改进的真实数据。最有价值的见解通常来自 Agent 在哪些地方遇到困难、升级或无法提供高质量解决方案的地方。使用这些信号改进你的内容、优化设置，并持续监控性能。

迭代和改进

将持续维护纳入工作流程

知识管理是一个过程。它不会在你发布一定数量的帮助文章后就结束。

随着你的产品、客户和业务目标的发展，你的支持内容也应该随之发展。这意味着你需要将"更新和创建新内容"持续纳入团队的工作流程。这不应该只在新功能推出前的匆忙中完成。

规划出更新内容的计划，概述：

  • 谁负责刷新或创建新内容。
  • 多久应审查现有内容以免变得陈旧。
  • 何时应该这样做——每天一小时、每个星期五、每月或任何对团队有意义的频率。

如果你使用 Fin，Operator 可以帮助你保持知识与业务变化同步，识别团队需要创建、更新或删除的确切内容，然后为你起草这些更改。
