对话设计：如何让你的 AI Agent 像你的团队一样沟通

如果你的团队中没有人受过训练来定义你的 Agent 如何沟通，它在与客户对话时会听起来像一个 LLM（因为它确实是）。

对话设计（Conversation Design）是 AI 优先支持团队中新兴的一门学科，旨在解决这个确切的问题。对话设计师负责定义 Agent 如何沟通：语气、结构、详细程度、客户体验、交接和升级流程。

如果没有一个专门的负责人来定义 Agent 应遵循的沟通指导，它会自己做出决策。这可能导致它在短答案就足够时给出过多细节，在客户沮丧时以平淡的语气回复，或过晚触发交接。

所有这些的成本都是可衡量的。收到结构尴尬回复的客户不太可能信任答案，即使答案准确，因此他们会升级到人工队友，以不同的方式听到同样的事情。其他人会完全跳过 Agent。当 Agent 确实交接时，糟糕的过渡意味着人工支持代表继承的是一个已经沮丧的客户。每一个这样的结果都是可以避免的，对话设计是确保它们不会发生的学科。

我们在 Fin 亲眼见证了这一点。我们对两条开场消息进行了 A/B 测试，一条温暖且对话性强，另一条是我们较旧的默认消息。对话性问候将 CSAT 从 72.8% 提升到 78.4%。一个单一的对话设计变更，应用于客户看到的第一件事，产生了可衡量的差异。

对话设计涵盖的内容

这个角色涵盖五个不同的领域，每个领域都塑造客户体验的不同部分：

领域 描述
语气和个性 声音、详细程度、Agent 听起来有多正式或随意，以及这是否根据情况而变化。
响应结构 Agent 是否将详细程度与客户的询问相匹配。
交接逻辑 何时升级、如何沟通过渡、以及携带什么上下文。
交互流程 对话如何在问题、答案、解决或交接之间进展。
响应质量 答案是否感觉清晰、有帮助且符合品牌调性，即使技术上正确。

如何付诸实践

从对话应有的感觉开始

在调整单个响应之前，先定义声音。用一段话写下你希望 Agent 听起来如何。你不需要完整的品牌指南，只需要一个在做出语气决策时可以参考的基准。

不同的对话类型可能需要不同的语体。一个被锁定账户的客户需要直接和速度，而探索新功能的人可能欣赏更多上下文。声音保持一致，但语体应该适应。

仔细设计交接

从 Agent 到支持代表的过渡是摩擦最高的时刻之一。客户不应该不得不重新解释他们的问题。代表应该收到完整的对话历史、问题背后的上下文、Agent 已经做了什么，以及为什么发生升级。

Agent 沟通交接的方式也很重要。"让我为您连接一位可以帮助处理此事的队友"的感觉不同于静默交接。

设计故障保险也至关重要。如果 Agent 无法干净地解决对话，你需要一个仍然给客户流畅交接体验的备用方法。客户可能在那时对 AI 沮丧，但处理得当的过渡可以扭转局面。

不要忘记跟进

跟进需要与交接同样的关注。如果有人在对话中途退出，与你的 Agent 或支持代表，你如何重新联系以确保他们得到了所需的帮助？大多数团队不考虑这个，但客户会注意到。

知道 Agent 何时应该停止说话

最常见的对话设计错误之一是过度解释。Agent 可以访问大量信息，如果不加引导，它很容易给出比客户需要更多的细节。

Agent 应该将详细程度与客户的询问相匹配。询问如何重置密码的人不需要三个段落。询问复杂集成的客户可能需要。如果有更多要分享的内容，它应该提供而不是一次全部给出。

为客户正在进行的对话设计

客户不遵循脚本。他们在对话中途改变方向，或提出与其原始问题无关的后续问题。

Agent 需要处理这些过渡，而不强迫客户回到固定流程。当客户已经继续前进后，Agent 仍然试图解决原始问题时，会感觉像在与一个没有在倾听的人交谈。

考虑相同的流程是否应该适用于不同的渠道，以及不同的客户群体是否需要不同的体验。

保持你的指令简短

最大的实际挑战之一是对 Agent 的过度指令。每次出现新的边缘情况时，团队都会添加规则。不久之后，LLM 在响应之前需要处理段落的指令。

我在 Fin 见过这种情况，也从其他团队那里听到过同样的情况。本能总是添加更多，但纪律是知道何时停止。

我的规则：如果是关于内容或信息，它属于知识库。如果是关于语气或如何处理特定情况，它属于你 Agent 的指令。关于定价要直接比一段解释定价沟通策略背后的哲学更有用。

如果你正在使用 Fin，很多工作在 Guidance 中进行。这是对话设计成形的地方，帮助你定义 Agent 应该如何听起来、应该说多少，以及在不同情况下应该如何响应。

无需专职人员如何开始

大多数团队在第一天不会雇用专门的对话设计师——这没问题。但需要有人负责 Agent 如何沟通，即使这是现有角色的一部分。

对话设计通常从支持运营或知识管理开始。团队中的某人开始关注 Agent 的声音。随着你的 Agent 处理更多对话，这成为一个正式的责任，并最终成为一个专门的职位。

从哪里开始

1. 指定一个负责人

你需要有人对 Agent 如何沟通负责。不需要是新雇员，但需要明确指定。

2. 选择一个效果不佳的对话类型

查看你的 Agent 正确回答但客户仍然升级或留下负面反馈的对话。从那里开始。

如果你正在使用 Fin，CX Score 可以帮助你发现这些。它显示哪些主题和对话类型得分较低，以及这些分数背后的原因，这样你可以看到问题是答案质量、客户努力还是其他什么。

3. 审计你的 Agent 指令

如果它们已经超出了几条集中的规则，修剪它们。将内容移到知识库中，保持指令专注于行为。

4. 修复你最糟糕的交接

查看一些 Agent 升级到人工的对话。客户是否不得不重复自己？支持代表是否有足够的上下文？首先重新设计那个单一的过渡。

小步骤的复利效应

这些改进中的每一个的影响都在复合。温暖的开场消息提高了我们的 CSAT，而修剪指令使响应更敏锐。设计更好的交接意味着支持代表不再继承沮丧的客户。

这些变化都不需要新知识；它们需要有人关注对话本身。
